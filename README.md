# Анализ кредитного риска по публичной отчётности

Проект собирает финансовую отчётность RFSD, события рейтингов и дефолтов, а
также сохраняет опубликованные документы. Текущий шаг — получить признаки
тональности и построить исследовательский прогноз на следующий год.

## Рабочая последовательность

Создать отдельное Python-окружение и поставить библиотеки для прогнозов и
анализа тональности можно так:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-forecast.txt -r requirements-sentiment.txt \
  --extra-index-url https://download.pytorch.org/whl/cpu
```

Дополнительный индекс позволяет pip выбрать CPU wheel PyTorch; если для
платформы такой wheel недоступен, установку следует выполнять по официальной
инструкции PyTorch для нужной платформы.

1. Запустить сбор данных `python main.py` в настроенном Python-окружении.
   Сборщик обращается к внешним сайтам; для e-disclosure нужен браузер и иногда
   ручное прохождение капчи. Полная сборка всего сборщика в контейнер здесь пока
   не предусмотрена.
2. Для анализа тональности установить зависимости
   `python -m pip install -r requirements-sentiment.txt`. RuBERT загружается при первом
   документе; для загрузки весов модели требуется доступ к Hugging Face.
   PDF с текстовым слоем обрабатываются напрямую. Сканированные PDF требуют
   OCR, который пока не подключён.
3. Сохранить созданный `company_analysis_*.csv` и построить прогноз:

   ```bash
   python forecast_credit_risk.py company_analysis_20261016_120000.csv
   ```

   По умолчанию результат записывается в `credit_risk_forecasts.csv` рядом с
   входным CSV. Можно указать другой путь через `--output`. Для исторической
   проверки прогнозов с известными фактическими метками добавьте:

   ```bash
   python forecast_credit_risk.py company_analysis_20261016_120000.csv \
     --backtest-output credit_risk_backtest.csv
   ```

   Бэктест строит прогноз на следующий календарный год для каждой доступной
   исторической пары и записывает фактические `actual_default` и
   `actual_rating_score`. Для каждой даты прогноза обучение ограничено
   целевыми годами, уже наступившими к этому моменту. По этим данным можно
   рассчитать метрики на отложенных годах; сам экспорт метрики и калибровку
   вероятностей не выполняет.

## Docker: прогноз и тесты

Docker-образ намеренно ограничен обработкой уже собранного CSV и unit-тестами.
Он не запускает парсеры внешних сайтов или RuBERT. Это позволяет проверять
обучающий этап без браузера, загрузки модели и тяжёлых NLP-зависимостей.

Нужны Docker Engine и Docker Compose:

```bash
docker compose build
docker compose run --rm test
docker compose run --rm forecast \
  forecast_credit_risk.py /workspace/company_analysis_20261016_120000.csv \
  --output /output/credit_risk_forecasts.csv
```

Входной CSV должен находиться в каталоге проекта; результат будет в
`diss/output/credit_risk_forecasts.csv`. CSV и прочие локальные данные
исключены из build context через `.dockerignore`.

Если `docker --version` работает, но Docker-команды сообщают, что не удаётся
подключиться к `/var/run/docker.sock`, установлен только Docker CLI или
остановлен Docker Engine. Запустите Docker Desktop/Engine и повторите команды.
Наличие `slirp4netns` само по себе не означает, что Docker daemon запущен.

## Интерпретация результата

`estimated_default_probability` — экспериментальная оценка Logistic Regression,
а не калиброванная PD для кредитных, юридических или регуляторных решений.
Существующая метка дефолта строится по найденным публикациям о дефолте по
облигациям: ноль означает «событие не обнаружено», а не доказанное отсутствие
дефолта у любого кредитора.

Модель использует пары соседних календарных лет: признаки за год `t` и целевой
рейтинг/дефолт за `t+1`. При обучении прогноза на год `t+1` берутся только
метки, чей целевой год не позже `t`, чтобы более поздние события не попадали в
обучение. Пропуск промежуточного года не считается парой.
Прогноз оставляется пустым, если для цели не накоплено минимальное число
обучающих меток; причина записывается в `default_model_status` или
`rating_model_status`. Перед исследовательским или прикладным использованием
необходимо провести проверку качества на отложенных по времени данных и
калибровку вероятностей.
